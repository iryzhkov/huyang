# Compact plan receipts

In the experimental profile, change_plan also accepts response_mode: "compact". Receipts retain plan ID/revision/state, invariant results, verification stages, missing coverage, explicit provisional acceptance and canonical change/revision fields. Bulky operation bodies, preview diffs, historical events and tool deltas are omitted from the concise presentation. The receipt points to change_plan inspect with response_mode: "full" for complete details. include_diagnostics: true retains full preparation details when requested. Refusal envelopes remain intact.

This is presentation only: durable plan records, journal commits, evidence strength, revision fences and provisional-acceptance rules are unchanged. Compact mode is not a byte cap for verification metadata.

The known source-read bound applies per target to selected/rendered UTF-8 content; JSON escaping, metadata and acquisition memory remain outside that cap. Search output bounding is deferred: a focused byte read provides the requested excerpt workflow, while changing search rendering and range-handle discovery merits separate scope. Fresh participants must demonstrate the user goal before final validation is claimed.
